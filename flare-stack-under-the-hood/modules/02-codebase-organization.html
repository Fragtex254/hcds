代码库的组织方式

如果你让 AI 帮你改博客的评论功能，它应该改哪个文件？如果你说「改评论那个文件夹里的代码」，你已经比大多数人强了。但具体是哪个文件呢？

图书馆的秘密

想象你走进一座图书馆。你不会看到一个巨大的房间把所有书胡乱堆在一起——文学区、科学区、历史区，每个区域有自己的书架排列方式和管理员。

代码库也是这样。博客的每个功能模块——文章、评论、搜索——就像图书馆的一个分区，有自己独立的空间。

📚

分区 = 功能模块

每个功能一个文件夹，互不干扰

📋

书架 = 数据层

存放和检索原始资料

⚙️

管理员 = 服务层

判断该怎么做，协调各项工作

📝

前台 = API 层

接收请求，转发给对应区域

理解这个结构，你就能精准地告诉 AI：「把这段逻辑放在服务层」，而不是让它乱放。

走进「文章」分区

让我们打开文章功能的文件夹，看看里面的结构：

features/posts/ 文章功能的全部代码
data/ 数据层：纯数据库查询
posts.data.ts 文章的数据库操作（查、改、删）
services/ 服务层：业务逻辑 + 缓存编排

schema/ 数据结构定义
posts.schema.ts Zod 验证 + 缓存键
api/ API 层：Server Functions
posts.queries.ts 查询（读操作）
posts.mutations.ts 变更（写操作）

同样的结构也出现在 features/comments/、features/tags/ 等每一个功能模块中。一旦你理解了一个，就理解了全部。

三层架构

每个功能模块的核心代码都遵循同一套三层结构。就像图书馆的每个分区都有书架区、管理室和借阅台。

🗄️
数据层（data/）

只做一件事：数据库查询。不关心缓存，不关心业务逻辑，纯粹的读写操作。

⚙️
服务层（service）

编排业务逻辑 + 缓存策略。决定「先查缓存还是直接查数据库」「数据要不要做额外处理」。

🔌
API 层（api/）

请求入口。接收HTTP 请求，验证参数，然后转发给服务层。它是「薄薄的」一层——几乎不包含任何业务逻辑。

💡
关键洞察：关注点分离

关注点分离——每个代码层只做自己的事。数据层不管缓存，API 层不管业务逻辑。改动一层不会影响其他层。

服务层：缓存与业务的指挥官

这是文章模块中「根据网址查找文章」的服务层代码。注意它如何协调缓存和数据库——先查缓存，缓存没有才去数据库。

CODE 
export async function findPostBySlug(
  context: Context,
  slug: string,
) {
  const version = await CacheService.getVersion(context, "posts:detail");
  const cacheKey = [version, "post", slug] as const;

  const post = await CacheService.get(
    context,
    cacheKey,
    PostWithTocSchema,
    async () => {
      const post = await PostRepo.findPostBySlug(context.db, slug);
      if (!post) return null;
      if (post.publicContentJson) {
        const { publicContentJson, ...rest } = post;
        const content = contentSchema.parse(publicContentJson);
        return { ...rest, content, toc: generateTocFromContent(content) };
      }
      const content = await highlightCodeBlocks(post.contentJson);
      const { contentJson, ...rest } = post;
      context.executionCtx.waitUntil(
        PostRepo.updatePublicContentSnapshot(context.db, post.id, content),
      );
      return { ...rest, content, toc: generateTocFromContent(content) };
    },
  );
  return post;
}

API 层：薄薄的转发层

对比一下 API 层的代码。它只做了三件事：接收请求、验证参数、转发给服务层。
