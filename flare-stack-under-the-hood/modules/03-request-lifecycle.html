请求的一生

你在浏览器地址栏输入博客网址，按回车。0.5 秒后，完整的网页出现了。这 0.5 秒里，你的请求穿越了多少个「关卡」？

一封信的旅程

想象你寄出一封信。它不会直接飞到收件人手里——它先到邮局分拣中心，按邮编分类，检查地址是否合法，再决定走哪条路线投递。

一个HTTP 请求也是如此。从浏览器发出，要经过CDN、Worker、路由层、中间件，最终变成你看到的网页。

理解这条路径，你就能在出问题时知道该排查哪一层。是 CDN 没缓存？路由写错了？还是数据库查询太慢？

第一站：Worker 入口

每个请求到达Cloudflare Workers 后，第一个执行的文件就是这个入口。它只有几行——职责是启动 Hono 应用并处理多语言。

CODE 
import { app } from "@/lib/hono/routes";
import { paraglideMiddleware } from "@/paraglide/server";

export const appWorkerHandler = {
  fetch(request: Request, env: Env, ctx: ExecutionContext) {
    return paraglideMiddleware(request, () =>
      app.fetch(request, env, ctx)
    );
  },
};

分拣规则：Hono 路由表

请求进入 Worker 后，Hono 路由表就是分拣中心的规则手册。每条规则对应一个 URL 模式。

CODE 
export const app = new Hono<{ Bindings: Env }>();

// 1. 所有 GET 请求先检查缓存
app.get("*", cacheMiddleware);

// 2. 公开 API 路由
const publicApi = new Hono<{ Bindings: Env }>()
  .route("/posts", postsListRoute)
  .route("/post", postsDetailRoute)
  .route("/tags", tagsRoute)
  .route("/search", searchRoute);
app.route("/api", publicApi);

// 3. RSS、sitemap 等站点文档
app.route("/", siteDocumentsRoute);

// 4. 认证路由（带限流和人机验证）
app.get("/api/auth/*", baseMiddleware, forwardAuthRequest);

// 5. 防护层：未知路径返回缓存的 404
app.all("*", shieldMiddleware);

// 6. 兜底：交给 TanStack Start 渲染
app.all("*", (c) => {
  return handler.fetch(c.req.raw, {
    context: { env: c.env, executionCtx: getExecutionContext(c) },
  });
});

安检关卡：中间件链

路由匹配到之后，还需要通过一系列安全检查。中间件就像机场安检——每一层检查不同的东西，层层递进。

CODE 
// 注入数据库连接
export const dbMiddleware = createMiddleware({ type: "function" })
  .server(async ({ next, context }) => {
    const db = getDb(context.env);
    return next({ context: { db } });
  });

// 解析用户会话
export const sessionMiddleware = createMiddleware({ type: "function" })
  .middleware([dbMiddleware])
  .server(async ({ next, context }) => {
    const auth = getAuth({ db: context.db, env: context.env });
    const session = await auth.api.getSession({
      headers: getRequestHeaders(),
    });
    return next({ context: { auth, session } });
  });

// 要求登录
export const authMiddleware = createMiddleware({ type: "function" })
  .middleware([sessionMiddleware])
  .server(async ({ next, context }) => {
    if (!context.session) throw createAuthError();
    return next({ context: { session: context.session } });
  });

// 要求管理员权限
export const adminMiddleware = createMiddleware({ type: "function" })
  .middleware([authMiddleware])
  .server(async ({ context, next }) => {
    if (context.session.user.role !== "admin")
      throw createPermissionError();
    return next({ context: { session: context.session } });
  });

把数据库连接注入到上下文中，传给下一个中间件

第二关：创建会话解析中间件

它依赖第一关——先确保数据库连接存在

从请求头中解析出当前用户的会话信息

用数据库连接初始化认证系统

查找这个请求对应的用户会话

从请求头中获取认证信息

把认证系统和会话信息注入上下文

第三关：登录验证中间件

它依赖第二关——先确保会话已解析

从上下文取出会话

如果没有会话（未登录），直接拒绝——抛出认证错误

已登录则放行，把会话传下去

第四关：管理员权限验证

它依赖第三关——必须先登录

从上下文取出已验证的会话

检查用户角色是否为管理员

不是管理员，直接拒绝——抛出权限错误

是管理员则放行

🧭
层层递进的安检

四个中间件形成一条链：dbMiddleware → sessionMiddleware → authMiddleware → adminMiddleware。每一层在前一层的基础上增加检查。如果中间任何一层检查不通过，请求直接被拒绝，不会到达后面的代码。

请求路径的六层关卡

一个请求从发出到最终看到网页，至少要经过这六层。每一层解决一个特定的问题。

⚡

CDN 缓存

全球边缘节点缓存页面。命中则直接返回，速度最快。就像小区门口的快递柜——不用去邮局。

📦

Cache API

Worker 内部的缓存层。CDN 没命中时，再查 Cache API。就像邮局内部的待发件架子。

🗂

Hono 路由器

根据 URL 路径分发请求到对应的处理程序。就像邮局的分拣机按邮编分类。

🛡️

中间件链

安全检查——身份验证、权限检查、频率限制。层层递进，不通过就拒绝。

🎨

TanStack SSR

服务器端渲染：加载数据、生成完整 HTML。就像分拣员把信件内容抄写到信纸上。

🗄️

D1 数据库

最终的数据来源。所有文章、评论、配置都存在这里。就像邮局的总仓库。

请求从上到下逐层穿透，每一层都有可能提前返回。如果 CDN 命中缓存，后面的层完全不用执行。
