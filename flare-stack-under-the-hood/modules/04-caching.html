核心机制：读穿缓存

读穿缓存是最常用的缓存模式。先查缓存，命中就返回；没命中就去数据库查，顺便把结果存到缓存里。下次就不用查数据库了。

CODE 
export async function get<T>(
  context: BaseContext & { executionCtx: ExecutionContext },
  key: CacheKey,
  schema: T,
  fetcher: () => Promise<z.infer<T>>,
  options: { ttl?: Duration } = {},
): Promise<z.infer<T>> {
  const { ttl = "1h" } = options;
  const serializedKey = serializeKey(key);

  // 1. 先查 KV 缓存
  const kvData = await env.KV.get(serializedKey, "json")
    .catch(/* 容错 */);

  if (kvData !== null) {
    const result = schema.safeParse(kvData);
    if (result.success) return result.data;
  }

  // 2. KV 未命中，回源数据库
  const data = await fetcher();
  if (data === null) return data;

  // 3. 后台写入缓存，不阻塞响应
  context.executionCtx.waitUntil(
    set(context, key, JSON.stringify(data), { ttl }),
  );

  return data;
}

关键洞察：waitUntil 的魔法

executionCtx.waitUntil() 告诉 Cloudflare「这个操作很重要，请在后台完成它，但不用等它结束再返回响应」。这就是为什么缓存写入不会拖慢用户看到的响应速度。

最难的问题：缓存失效

「计算机科学只有两个难题：缓存失效和命名。」—— Phil Karlton。这个项目用版本号失效优雅地解决了缓存失效问题。

CODE 
// 读取当前版本号
export async function getVersion(context, namespace) {
  const key = `ver:${namespace}`;
  const v = await context.env.KV.get(key)
    .catch(/* 容错 */);
  if (v && !Number.isNaN(Number.parseInt(v))) {
    return `v${v}`;
  }
  return "v1";
}

// 版本号 +1，旧缓存全部作废
export async function bumpVersion(context, namespace) {
  const key = `ver:${namespace}`;
  const current = await context.env.KV.get(key)
    .catch(/* 容错 */);
  let next = 1;
  if (current) {
    const parsed = Number.parseInt(current);
    if (!Number.isNaN(parsed)) next = parsed + 1;
  }
  await context.env.KV.put(key, next.toString());
}

🧩
为什么版本号这么巧妙？

缓存 key 包含版本号（如 v3/post/hello-world）。bumpVersion 把版本号从 3 变成 4，所有以 v3 开头的旧 key 永远不会被查到——它们等效于「不存在」。不需要逐个删除，一次 bump 就能让整个命名空间的所有旧缓存失效。

export async function findPostBySlug(context, slug) {
  // 1. 获取当前缓存版本号
  const version = await CacheService
    .getVersion(context, "posts:detail");
  // 2. 将版本号拼入缓存 key
  const cacheKey = [version, "post", slug];

  // 3. 读穿缓存：先查 KV，miss 时回源数据库
  const post = await CacheService.get(
    context,
    cacheKey,
    PostWithTocSchema,
    async () => {
      const post = await PostRepo
        .findPostBySlug(context.db, slug);
      if (!post) return null;
      // ... 处理高亮、目录生成 ...
      return processedPost;
    },
  );
  return post;
}

三种缓存失效策略

缓存写入容易，失效才是难题。这个项目使用三种策略，每种适用于不同的场景。

🔄

版本号 bump

一次 bump 就能让整个命名空间的所有旧缓存失效。不知道有哪些 key 也没关系。用于文章发布、全站刷新等场景。

🎯

精确 key 删除

直接删除指定的缓存 key。精准、高效，但需要知道要删哪个 key。用于删除评论、更新单篇等场景。

🌍

CDN Purge API

调用 Cloudflare API 清除全球 CDN 缓存。代价最大但覆盖最全，用于站点级更新、域名切换等场景。

实际更新文章时，三种策略会组合使用：先 bump 版本号让 KV 缓存失效，再调用 CDN Purge API 清除边缘缓存。这就是为什么管理员更新文章后，全球用户很快就能看到最新版本。
